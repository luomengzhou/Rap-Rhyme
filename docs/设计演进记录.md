# Rap Rhyme 设计演进记录

这份文档记录这个网站是怎么一步步长成现在这样的：最初想做什么，后来每次想到了什么、为什么要加、最后做成了什么样。按时间顺序写，新的功能接着往下加。

最初的完整规划在这里：[说唱写词辅助网站 · 规划草案](https://claude.ai/artifact/XMsT2pk2rfQP5G77gZhGsy)（私有文档，只有作者能打开）。

## 怎么往下加

每做一个新功能，在「演进记录」最后加一节，照这个格式写：

```
### 编号 · 功能名（日期）
- **起因**：当时遇到了什么，或者想到了什么。
- **做法**：做成了什么样，关键的取舍是什么。
- **状态**：PR 编号，上线没有，哪些地方还没验证。
```

如果一个想法定下来但还没做，放进最后的「想过但还没做」。做了之后从那里划掉，搬到演进记录里。

## 初衷

一个给说唱新人用的写词工作台。最开始的想法是这样一条线：

- 有了想法，能找到合适的词。想押某个韵时，能查到这个韵有哪些词，从单押到双押、三押、四押。
- 完全押韵会变成数来宝，所以押韵要和 flow 一起看。
- 想写某种气质（比如暗黑、戏谑）时，知道该用什么 beat、flow 大概什么样、有哪些经典的歌和歌手可以去听。
- 知道一首歌怎样算规整，大概几句话。
- 不限中文，英语和韩语也要。
- 有典故、隐喻、梗和 wordplay 的库，支持明线暗线的写法。
- 能标记自己喜欢什么，能反馈「这几句不行」，让工具学会口味。
- 参考歌曲和歌手做成星云的样子，点一颗星就飞到它附近，背后是向量化的相似度。

## 一直不变的原则

这些是在规划阶段陆续定下来的，后面每个功能都照着做。

1. **表达优先**。表达才是最重要的，不为了押韵本末倒置。所有建议都要尽量不改意思，改了意思要明说。
2. **雷点是硬过滤**。大量讲性、炫耀钱和名气、物化女性、吸毒，这几类题材的词不写也不推荐。这类歌的 beat 和节奏可以参考。
3. **只给真词**。试用过两个现成的押韵软件，一个把不押韵的词当成押韵，一个给出字典里查不到的凑字词。所以这里只给词典里真实存在的常用词，生僻词默认藏起来，默认严格押，宽押要标出来。
4. **数字只是提醒**。每小节多少字、一段多少行这些都是温和的提醒，不是框架，不拦人。
5. **原稿不动**。任何修改都另存一份，不覆盖原来写的词。
6. **不编造**。素材和出处要能核对。工具听不到歌，所以不对具体某首歌的细节下结论。
7. **只存必要的东西**。记录别人歌里的韵脚时，只存押韵的词、歌名和歌手，不存整首歌词。自己的歌词不进公开仓库。
8. **自用优先**。目前只给作者自己用，电脑上用为主，不接付费 API。

## 演进记录

### 0 · 规划（2026-11-24）
- **起因**：先计划，再动手。
- **做法**：调研了现有工具，写了规划草案，分三期。规划过程中又加进来这些想法：
  - 文学素材。诗词、散文、故事、神话寓言都可以是素材来源，按概念（比如「春日恋爱」）找可以化用的作品，附真实出处。
  - 唱法和乐理。先定想怎么唱（狠、抒情等），再得出吐字速度、主歌和 hook 大概多长。乐理按「一个经典例子加一段理论总结」的卡片来讲。
  - Flow 指纹。把一句词记成节奏码（比如 2-2-2），可以从词找相似节奏的歌和 beat，也可以反过来。
  - 韵脚检查。像视频里那样用彩虹色标出韵脚，既能查别人的歌，也能查自己正在写的词。确认过的韵脚进一个带出处的韵脚库。
  - 相似歌曲。只看歌曲本身的特征来算「像不像」，不带个人偏好。
  - 空格打拍。按空格记下脑子里那句话的节奏，是输入节奏的主要方式。
  - 不规整的结构。有了不规整的想法时，找结构相近的现成歌去听，再决定照着写还是改规整。
- **状态**：规划完成，决定开工。

### 1 · 第 1 期：中文写词工作台（2026-11-24）
- **起因**：需求已经比较完整，押韵结果好不好只有做出来才知道。
- **做法**：
  - 找韵：单押到四押，只给真词，生僻词默认隐藏，不满意的词可以永久屏蔽。
  - 韵脚检查：写词或贴词时自动上色，统计双押次数，提醒「像数来宝」或「这句太长」。
  - 唱法和字数：选唱法和 BPM，给出每小节、每段大概多少字。
  - 打拍：按空格记录节奏，得到节奏码，可以把词贴到落点上。
  - 示例 beat、结构模板、乐理卡。
  - 取舍：没有后端，做成纯静态网站，草稿只存在浏览器本地。
- **状态**：PR #1，已合并，部署在 GitHub Pages。

### 2 · 改稿页：分屏看改前改后（2026-11-24）
- **起因**：想让工具读完一整首词之后，看出想押什么韵、主题是什么，给结构和换词的建议，并推荐手法相近的歌。而且希望在网站上看，不是在聊天里看，像代码评审那样有改前改后的分屏，原稿不能被删。
- **做法**：新增「改稿」页。左边原稿，右边改后，逐行对齐。每条建议是一张卡片，带分类（押韵、结构、长度、表达）和理由，可以单独接受或撤回，有多种写法时可以点选。满意后「存为新草稿」。第一版的建议是一份导入的文件。
- **状态**：PR #2，已合并。

### 3 · 在网站里直接和 Claude 对话（2026-11-24）
- **起因**：导入文件还是等于复制粘贴，想要的是在网站上直接对话。
- **做法**：把同一个网站另外发布到 claude.ai 上，用登录的 Claude 账号对话，不需要 API key。改稿页右边是对话框，Claude 能看到草稿，它提的具体改动自动变成分屏里的建议。
- **取舍**：从此有两份网站。claude.ai 那份有对话，GitHub Pages 那份没有。两边的草稿不互通。
- **状态**：PR #3，已合并。

### 4 · 分段、长短、下一步引导、听歌笔记（2026-11-24）
- **起因**：贴一段词进来，希望能自动分出 verse、hook、intro、outro。不确定自己的词算不算短。写到一定程度该配 beat 了，不知道下一步怎么走。平时听歌觉得某一段适合某种词，想存下来。
- **做法**：
  - 「让 Claude 帮我分段」，分段结果作为一条建议在分屏里确认。
  - 按 BPM 估算时长，可以问长短怎么选。
  - 六步引导，从分段、定速度、打拍到找 type beat、录一遍再改。
  - 「听歌笔记」页：歌名、歌手、位置、适合哪段词或哪种风格、想学它什么。
- **状态**：随 PR #3 合并。

### 5 · 构思模式和素材库（2026-11-24）
- **起因**：有的歌只有主题和分段想法，还没有词。想在工作台里聊主题，看相关的典故和意象。参考来源不限说唱，流行歌也可以。
- **做法**：
  - 草稿为空或很短时，对话自动变成构思模式，可以出带分段标题的提纲并写进草稿。
  - 典故、诗词、意象、歌曲以卡片给出，可以收藏到「素材」。每张卡片有「搜原文核对」的链接。
  - 可以自己加素材、改素材，比如把查到的原版歌词贴进去。
  - 外语素材可以翻译成中文。
- **中途修的问题**：点收藏后页面跳回顶部；素材库一开始不能自己新增。
- **状态**：随 PR #3 合并。

### 6 · 哼唱分析（2026-11-25）
- **起因**：想像录语音备忘录那样哼一段节奏，让工具切出节奏型和重音，找相近的节奏，并配上想要的音色。
- **做法**：新增「哼唱」页。上传或录一段声音，切出每一下并标重音，粗分成咚、哒、叮三类，估出速度，落到 16 格里。可以改格子、回放、换音色、对比几种通用的节奏骨架、存到打拍页、交给 Claude 描述成找 beat 的关键词。
- **后续升级**：
  - 切分方法换成频谱分析（28 个频段找起点，用频谱重心分闷和亮）。
  - 可以导出 Strudel 代码，并直接在 strudel.cc 打开。
  - claude.ai 不给页面开麦克风，所以页面内录音只在 GitHub Pages 那份上能用。
- **状态**：PR #4，已合并。只用合成声音测过，真人哼唱没有验证。

### 7 · 素材共用和划句翻译（2026-11-25）
- **起因**：存为新草稿后素材看起来「清空」了。整段翻译又长又带符号，不好看。
- **做法**：素材改成所有草稿和版本共用一份。翻译改成划哪几句就翻哪几句（一次最多 8 行），译文夹在原文下面。整段只给折叠的大意。去掉了每张卡片上重复的提示。
- **状态**：PR #4，已合并。

### 8 · 韵脚本（2026-11-25）
- **起因**：看别人的歌词时发现一串押在一起的词，想记成一组，写词时能优先看到，并标明出自哪首歌。
- **做法**：在素材卡片的歌词里划词，归成一组韵，每组有颜色和出处。也可以在找韵面板里手动加一组。查韵时，自己记过的韵组排在最前面，用框标出来。只存押韵的词和出处。
- **状态**：PR #4，已合并。

### 9 · 英文找韵（2026-11-25）
- **起因**：在找韵里输入英文什么都查不到。后来又遇到词典里没有的词（人名、俚语）。再后来发现查出来的英文词有的不认识。
- **做法**：
  - 加了英文发音词典，约 4 万个常用词。严格押比较重读元音和后面的辅音，宽押只比元音。
  - 词典里没有的词，可以让 Claude 给读音，或者自己填「读起来像哪个词」。
  - 每个英文结果可以显示中文意思。
- **状态**：PR #4，已合并。韩语和日语的找韵还没做。

### 10 · 改后一栏可以自己改（2026-11-25）
- **起因**：Claude 的建议给了灵感，但不想完全照它的来。
- **做法**：改稿页的「改后」一栏可以直接手改，再存为新草稿。手改时接受一条建议，会把这条改动叠加到手改的版本上。
- **状态**：PR #4，已合并。

### 11 · 中文押韵规则微调（2026-11-25）
- **起因**：按耳朵听，an 和 uan 押得上，但它们和 ian、üan 押不上。原来的规则把这四个都算成一类。
- **做法**：严格模式下 an 和 uan 一组，ian 和 üan 一组。宽押模式下才合并。原则是规则跟着耳朵走。
- **状态**：PR #4，已合并。

### 12 · 拆歌（2026-11-25）
- **起因**：词的部分暂时够用了，想加强 beat 方面。想拆解一首 beat 变化很多但衔接和谐的歌，但是没有乐理基础，不知道从哪里下手。
- **做法**：新增「拆歌」页。一边听歌一边按键打点，给每一段用大白话选鼓的感觉、flow、情绪、怎么转场，可以敲出 BPM。拆完得到一份文字描述和一个可以套用的结构模板。全部由自己听、自己填，工具不替人下结论。
- **状态**：PR #4，已合并。

### 13 · 曲风分类（2026-11-25）
- **起因**：原来的 beat 列表是随手举的几个例子，太少。想换成说唱里正经的曲风分类，用它们的专有名词。
- **做法**：新增「曲风」页，51 个曲风分成 7 个家族，每个有英文名、中文名、常见 BPM、一句大白话说明、可以试听的示例鼓点和搜 beat 用的关键词。底部的 beat 选择也换成这套分类。
- **状态**：PR #4，已合并。示例鼓点是按曲风的通常特征写的，没有人工听过校对。

### 14 · 哼唱转旋律和 MIDI（2026-11-25）
- **起因**：看到编曲软件里有把音频自动转成 MIDI 的功能，想在这里也有类似的。
- **做法**：用开源的 Basic Pitch 模型，在浏览器本地识别哼唱的音高。给出音名、钢琴卷帘图、试听、Strudel 旋律代码和 MIDI 文件。
- **取舍**：只认有音高的旋律，鼓点仍用第 6 节的节奏分析。claude.ai 那份不能下载文件，MIDI 下载要在 GitHub Pages 那份上用。
- **状态**：PR #4，已合并。只用合成旋律测过，真人哼唱没有验证。

### 15 · 第二轮改进的总体方向（2026-11-26）
- **起因**：用了一轮之后，集中提了一批意见：立意比词更根本，想先写每段要表达什么；存档变成了一长串「改后（改后）」；唱法分类是随口想的；示例 beat 太假；写词和改稿分在两个页面，改稿时看不到韵脚；韵脚本想自动提取；打拍、哼唱、拆歌三个页面用途有重叠。

### 16 · 圆括号写释义，唱法换成说唱分类（2026-11-26）
- **起因**：有时已经想好每一段表达什么，但词还没写出来，想把立意和正经的歌词分开写。原来的唱法分类（狠、叙事、戏谑、慢热、抒情）不是说唱里通用的说法。
- **做法**：
  - 圆括号里的内容算释义，整行或夹在一行中间都可以。显示成另一种颜色，不计字数、不计小节、不参与找韵。Claude 读草稿时会把它当作立意来理解，不去改它。没有用斜体，因为编辑器靠两层文字对齐，斜体会让光标错位。
  - 唱法换成 9 个大类：Boom Bap、Storytelling / Conscious、Hardcore、Trap、Drill、Melodic Rap、Jazz Rap / Lo-fi、Chopper、Old School。每类有常见 BPM、每小节字数、hook 写法和吐字提示。快嘴的字数上限单独放宽。以前选过的唱法会自动对应到新的分类。
- **状态**：PR #6。

### 17 · 写词和改稿合成一个工作台（2026-11-26）
- **起因**：写词和改稿是两个页面，在改稿里看不到韵脚。改稿页的栏宽是固定的。在素材、建议、对话几个标签之间来回切，每次都回到最顶上，要重新滚。
- **做法**：
  - 去掉单独的「改稿」页。左边永远是带韵脚颜色的编辑器，上面可以切到「改前改后」看对比。右边一栏有六个标签：检查、找韵、结构、Claude、建议、素材。
  - 接受一条建议，或点建议的标题，左边自动切到「改前改后」并跳到那一行。
  - 左右两栏之间、原稿和改后之间的线都可以拖，宽度会记住。
  - 每个标签各自记住滚到了哪里，切走再回来还在原处。对话只在有新消息时才滚到底。
  - 顺手修了页面在窄一点的窗口里会横向溢出的问题。
- **状态**：PR #7。

### 18 · 歌曲、版本和备份（2026-11-26）
- **起因**：每次「存为新草稿」都多出一份「某某（改后）」，一首歌改几轮就变成一长串，分不清哪份是哪份。真正想要的是两件事分开：像提交代码那样的版本（V1、V2），和写的过程中怕丢内容的备份。备份不代表版本变了。
- **做法**：
  - 一首歌只有一份正在写的稿子，每次改动自动保存。
  - 「定稿为 Vn」才产生一个版本，要自己点。
  - 「存个备份」随时存一份，不算版本。另外每隔十来分钟自动备份一次，换掉稿子之前（采用改后稿、恢复旧版本）也会先备份。最多留 30 份，满了先丢自动存的。
  - 「版本和备份」里可以看每一份的内容，恢复或删除。
  - 改前改后里的「存为新草稿」改成「用这份改后稿」，直接写回这首歌。
  - 以前留下的「某某（改后）（改后）」自动收成同一首歌：前面几份变成 V1、V2…，最后一份是正在写的稿子，各份和 Claude 的对话接在一起。
- **状态**：PR #8。
